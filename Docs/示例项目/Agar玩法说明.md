# Agar玩法说明

本文只说明仓库中 `Agar` 示例代码的玩法背景，帮助读者理解教程里为什么会出现登录、匹配、房间、状态同步和排行榜等示例。

本文件不是新手教程主线。学习 ET8.1 时，请优先阅读：

[../教程/新手教程/00-教程索引.md](../教程/新手教程/00-教程索引.md)

## 示例定位

`Agar` 示例模拟类似《球球大作战》的实时多人吞噬成长玩法。

它在本仓库中的作用不是提供完整游戏，而是作为 ET8.1 教学用例，覆盖这些常见开发链路：

```text
客户端登录 Realm 和 Gate
客户端请求匹配
服务端创建房间
客户端上报移动输入
服务端权威计算房间状态
服务端向玩家推送状态和结算
客户端 UI 接收推送并刷新
```

## 玩法方向

核心玩法方向：

1. 玩家控制一个球体在开放竞技场中移动。
2. 通过吞噬地图资源或体积更小的玩家成长。
3. 体积越大移动越慢，体积越小越灵活。
4. 支持分裂、合体、喷射、追击、逃跑等实时对抗行为。
5. 服务端负责权威状态、碰撞判定、成长结算和同步。
6. 客户端负责输入、预测表现、相机、UI、动画和资源展示。

## 示例实现优先级

当前示例更关注教学链路，因此优先展示：

1. 单房间多人进入和离开。
2. 玩家移动、视野跟随、地图边界。
3. 食物刷新、吞噬、体积成长。
4. 玩家之间的吞噬判定。
5. 排行榜、结算、匹配和房间生命周期。

分裂、合体、喷射等进阶操作可以作为后续扩展示例，不是理解 ET8.1 基础教程的前置条件。

## 服务端权威思路

示例采用“服务端权威，客户端表现”的思路：

- 服务端维护房间、玩家球体、食物、质量、位置、速度和碰撞结果。
- 客户端只上传输入意图，例如移动方向。
- 客户端可以做平滑插值和预测表现，但最终状态以服务端同步为准。
- 吞噬判定、质量变化、死亡和结算在服务端完成。
- 地图资源刷新和房间生命周期由服务端统一驱动。

## 示例模块

教程中会看到这些示例模块名：

```text
Room              房间生命周期、玩家进入离开
Ball / Cell       玩家球体、质量、半径、速度
Food              地图食物刷新和回收
Input             客户端输入上报
Sync              服务端状态广播和客户端表现刷新
Collision         球体和食物、球体和球体的吞噬判定
Ranking           房间内排行榜和结算
```

这些命名是示例项目自己的业务命名，不是 ET 框架强制要求。
