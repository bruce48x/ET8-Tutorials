# 开发指南

本文定位为面向 ET 框架的通用教学指南：按主题解释 ET 项目中客户端、服务端、热更新、消息、配置、资源和工具链的开发方法，再用本仓库的实现作为示例。示例路径和命名可以替换成你自己项目里的模块名。

第一版先从客户端 UI 入手，主题是：自定义界面，以及让游戏从自己的启动入口创建界面。后续章节可以继续补充服务端房间、消息协议、状态同步、配置导出、资源打包等内容。

## 文档组织方式

本指南不是 API 速查表，也不是本项目的变更记录。每个主题都尽量按这个结构展开：

```text
先解释通用概念
再说明推荐做法
然后给出本项目示例
最后列出排查清单
```

当前章节使用 Agar UI 作为例子，但要学习的是 ET 的组织方式：模块隔离、事件驱动启动、Entity Component、热更程序集加载，以及 Unity prefab 与 ET UI Entity 的连接方式。

## 先理解界面的边界

在做 UI 之前，先不要急着复制 prefab 或写代码。先按游戏状态定义界面边界。

| 界面 | 出现场景 | 主要职责 |
| --- | --- | --- |
| 主界面 | 玩家未进入战斗房间时 | 登录、大厅、匹配入口、设置、玩家信息 |
| 战斗界面 | 玩家进入房间或战斗场景后 | 战斗 HUD、摇杆、技能按钮、质量/分数、排行榜、倒计时 |

判断原则：

```text
数据来源是账号、大厅、匹配状态，属于主界面。
数据来源是房间、玩家球体、实时同步状态，属于战斗界面。
```

这个判断方法比“看起来像哪个界面”更稳定。因为 UI 后续会越来越多，真正决定代码边界的是生命周期和数据来源。

## 不要直接改 Demo 示例

很多 ET 项目自带 Demo 等示例代码。学习时可以参考它们，但正式业务最好建立自己的模块，而不是直接修改 Demo 文件。

通用原则：

```text
Demo 目录用于学习框架写法。
正式玩法使用自己的目录、UIType、Component、Event 和启动入口。
```

以本项目为例，正式界面放在 Agar 目录下，而不是直接改 `Demo/UILogin`。

## UI 代码应该放在哪里

ET 的客户端 UI 一般分成“稳定定义”和“可热更行为”两部分：

| 内容 | 推荐位置 |
| --- | --- |
| UI 类型常量 | `ModelView/Client/<Module>/UI/UIType.cs` |
| UI Component 字段定义 | `ModelView/Client/<Module>/UI/<UIName>/<UIName>Component.cs` |
| UI 创建、资源加载 | `HotfixView/Client/<Module>/UI/<UIName>/<UIName>Event.cs` |
| 按钮绑定和界面行为 | `HotfixView/Client/<Module>/UI/<UIName>/<UIName>ComponentSystem.cs` |
| UI Prefab | `Assets/Bundles/UI/<Module>/<UIName>.prefab` |

本项目示例：

| 内容 | 示例路径 |
| --- | --- |
| UI 类型常量 | `Unity/Assets/Scripts/ModelView/Client/Agar/UI/UIType.cs` |
| UI Component 字段定义 | `Unity/Assets/Scripts/ModelView/Client/Agar/UI/UIAgarLogin/UIAgarLoginComponent.cs` |
| UI 创建、资源加载 | `Unity/Assets/Scripts/HotfixView/Client/Agar/UI/UIAgarLogin/UIAgarLoginEvent.cs` |
| 按钮绑定和界面行为 | `Unity/Assets/Scripts/HotfixView/Client/Agar/UI/UIAgarLogin/UIAgarLoginComponentSystem.cs` |
| UI Prefab | `Unity/Assets/Bundles/UI/Agar/UIAgarLogin.prefab` |

示例命名：

```text
UIAgarLogin
UIAgarLobby
UIAgarMatching
UIAgarBattle
```

如果换成其他项目，可以把 `Agar` 换成 `Game`、`Battle`、`Lobby` 或自己的业务模块名。

## Prefab 与 Component 如何关联

这是初学时最容易混淆的一点：ET 的 UI Component 不是 Unity `MonoBehaviour`，不会直接挂在 prefab Inspector 上。

关联发生在代码里的 `AUIEvent.OnCreate()`：

```csharp
string assetsName = $"Assets/Bundles/UI/Agar/{UIType.UIAgarLogin}.prefab";
GameObject bundleGameObject = await uiComponent.Scene()
        .GetComponent<ResourcesLoaderComponent>()
        .LoadAssetAsync<GameObject>(assetsName);

GameObject gameObject = UnityEngine.Object.Instantiate(
        bundleGameObject,
        uiComponent.UIGlobalComponent.GetLayer((int)uiLayer));

UI ui = uiComponent.AddChild<UI, string, GameObject>(UIType.UIAgarLogin, gameObject);
ui.AddComponent<UIAgarLoginComponent>();
return ui;
```

通用链路：

```text
UIType 常量
 -> [UIEvent(UIType.Xxx)] 注册创建器
 -> OnCreate 加载 prefab
 -> prefab 实例化为 GameObject
 -> GameObject 包进 ET 的 UI Entity
 -> UI Entity AddComponent<具体 UI Component>
 -> ComponentSystem.Awake 绑定按钮和子节点引用
```

也就是说：

```text
Prefab 负责视觉结构。
ReferenceCollector 负责暴露子节点引用。
ET Component 负责保存这些引用。
ComponentSystem 负责绑定行为。
```

Prefab 内部节点通常通过 `ReferenceCollector` 暴露给代码。代码里使用的 key 必须和 prefab 上的引用名一致：

```csharp
ReferenceCollector rc = self.GetParent<UI>().GameObject.GetComponent<ReferenceCollector>();
self.loginBtn = rc.Get<GameObject>("LoginBtn");
self.account = rc.Get<GameObject>("Account");
self.password = rc.Get<GameObject>("Password");
```

如果界面不显示或报空引用，优先检查：

```text
Prefab 根节点是否有 ReferenceCollector
ReferenceCollector 是否包含代码需要的 key
Prefab 路径是否和 OnCreate 中的 assetsName 完全一致
```

## 如何创建自己的启动入口

正规做法不是“把 Demo 的资源路径改成自己的 prefab”，而是为自己的模块建立独立启动入口。

通用结构：

```text
AppType.<Module>
SceneType.<Module>
[Event(SceneType.<Module>)]
UIType.<YourUI>
<YourUI>Event
<YourUI>Component
<YourUI>ComponentSystem
```

本项目 Agar 示例：

启动链路应为：

```text
GlobalConfig.AppType = Agar
 -> EntryEvent3_InitClient 读取 AppType
 -> root.SceneType = SceneType.Agar
 -> Publish AppStartInitFinish
 -> [Event(SceneType.Agar)] 被触发
 -> UIHelper.Create(root, UIType.UIAgarLogin, UILayer.Mid)
 -> UIAgarLoginEvent.OnCreate
 -> 加载 Assets/Bundles/UI/Agar/UIAgarLogin.prefab
```

关键点是保持这些名称一致：

```text
AppType.Agar
SceneType.Agar
[Event(SceneType.Agar)]
```

`EntryEvent3_InitClient` 会通过字符串把 `AppType` 转成 `SceneType`，因此 `AppType` 和 `SceneType` 的枚举名必须一致。

换成你的项目时，也要保持：

```text
AppType.你的模块名
SceneType.你的模块名
[Event(SceneType.你的模块名)]
```

## 启动检查清单

新增或调整 UI 后，按顺序检查。这里仍以 Agar 为例，其他模块把名字替换掉即可：

1. `UIType` 是否存在对应常量。
2. 是否存在 `[UIEvent(UIType.Xxx)]`。
3. `OnCreate()` 中的 prefab 路径是否正确。
4. Prefab 是否位于 `Unity/Assets/Bundles/UI/Agar/`。
5. Prefab 根节点是否配置 `ReferenceCollector`。
6. ComponentSystem 读取的 key 是否都存在。
7. 是否存在 `[Event(SceneType.Agar)]` 的启动事件。
8. `GlobalConfig.asset` 的 `AppType` 是否切到 `Agar`。
9. 修改热更代码后是否执行过 `ET/Compile`。

## 为什么 ET/Compile 很关键

很多 ET + HybridCLR 项目在 Editor 中也会启用 dll 加载模式。此时 Unity 自动编译出来的 `Library/ScriptAssemblies` 不一定是运行时真正加载的代码。

以本项目为例，`GlobalConfig.asset` 中启用 `EnableDll` 时，Editor 运行由 `CodeLoader` 加载：

```text
Unity/Assets/Bundles/Code/Unity.Model.dll.bytes
Unity/Assets/Bundles/Code/Unity.ModelView.dll.bytes
Unity/Assets/Bundles/Code/Unity.Hotfix.dll.bytes
Unity/Assets/Bundles/Code/Unity.HotfixView.dll.bytes
```

因此新增 UI 事件、ComponentSystem、SceneType 等代码后，必须执行 Unity 菜单：

```text
ET/Compile
```

或快捷键：

```text
F6
```

执行后确认 `Assets/Bundles/Code/*.dll.bytes` 的修改时间已经更新。否则常见现象是：

```text
源码里有 [Event(SceneType.Agar)]
GlobalConfig 也切到了 Agar
运行时仍然没有任何界面
```

这是因为运行时加载的还是旧热更 dll。

## 没出现界面时怎么定位

启动后没有出现目标界面时，按这个顺序排查：

1. 看 Unity Console 是否有编译错误。
2. 确认 `GlobalConfig.asset` 的 `AppType` 实际值是目标模块。
3. 执行 `ET/Compile`，确认 `Assets/Bundles/Code/*.dll.bytes` 已更新。
4. 确认 `AppType.<Module>` 和 `SceneType.<Module>` 都存在且名字一致。
5. 确认启动事件标注的是 `[Event(SceneType.<Module>)]`。
6. 确认 UIEvent 能加载到目标 prefab。
7. 确认 prefab 的 `ReferenceCollector` 引用完整。

优先区分两类问题：

```text
启动事件没有触发：通常是 AppType/SceneType 或 ET/Compile 问题。
启动事件触发但界面没出来：通常是 prefab 路径、资源收集或 ReferenceCollector 问题。
```

## 本项目参考约定

以下是本仓库目前采用的参考约定，不是 ET 框架强制要求：

- Demo 目录只作为 ET 示例参考，不承载本项目正式 UI。
- Agar UI 使用 `UIAgar*` 命名前缀，避免和 Demo 示例重名。
- 主界面、战斗界面按游戏状态划分，不按视觉外观划分。
- UI 行为放 `HotfixView`，UI 字段定义放 `ModelView`。
- 修改热更程序集相关代码后，运行前执行 `ET/Compile`。
