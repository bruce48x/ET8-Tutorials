# 部署打包与集群运维

这篇解释 ET 服务端如何定义集群、如何打包、如何启动关闭，以及崩溃和监控应该从哪里入手。

本仓库目前提供的是基础打包脚本和 ET 的启动配置结构。生产级部署还需要结合你的发布系统、进程管理和监控平台。

## 集群由什么定义

ET 的服务端集群不是写死在代码里的，而是由 StartConfig 定义。

常见文件：

```text
Config/Json/s/StartConfig/Localhost/StartMachineConfig.txt
Config/Json/s/StartConfig/Localhost/StartProcessConfig.txt
Config/Json/s/StartConfig/Localhost/StartSceneConfig.txt
Config/Json/s/StartConfig/Localhost/StartZoneConfig.txt
```

四类配置分别回答：

| 配置 | 回答什么问题 |
| --- | --- |
| `StartMachineConfig` | 有哪些机器，内网 IP、外网 IP、Watcher 端口是什么 |
| `StartProcessConfig` | 有哪些进程，每个进程在哪台机器、监听什么进程端口 |
| `StartSceneConfig` | 每个进程里有哪些 Scene、SceneType、业务端口 |
| `StartZoneConfig` | 有哪些区服，数据库连接是什么 |

## Localhost 示例

本仓库 `Localhost` 只有一个进程：

```text
StartProcessConfig: Process 1
```

但这个进程里有多个 Scene：

```text
Realm
Gate1
Gate2
Location
Match
RouterManager
Router01-04
```

所以新手不要把“进程”和“服务”混为一谈。一个进程可以承载多个 ET Scene。

## 如何打包

仓库根目录有：

```text
Publish-linux-x64.ps1
```

脚本做的事：

```text
dotnet publish -r linux-x64 --no-self-contained --no-dependencies -c Release
复制 Bin/linux-x64/publish 到 Publish/linux-x64/Bin
复制 Config 到 Publish/linux-x64/Config
```

这表示发布包至少需要：

```text
可执行文件和 dll
Hotfix.dll
Config/
```

实际项目还要确认日志目录、运行账号、系统服务配置、环境变量和数据库地址。

## 如何启动

服务端启动的核心参数来自 `Options`：

```text
--AppType Server
--StartConfig StartConfig/Localhost
--Process 1
```

含义是：

```text
以 Server 模式启动
读取 Localhost 这套启动配置
当前进程身份是 Process 1
```

如果要启动 Watcher，则使用：

```text
--AppType Watcher
```

Watcher 的职责是根据本机 IP 找到应该运行在本机的进程，并启动它们。

## 如何关闭

最基础的关闭方式是结束 dotnet 进程。

生产环境不建议只靠手动杀进程。更常见做法是：

```text
用 systemd、supervisor、容器编排或自研运维系统管理进程
关闭前从入口摘流量
等待已有玩家请求结束或踢下线
再停止进程
```

本仓库还没有完整的优雅停机脚本。教程里先理解 ET 的进程和 Scene 拓扑，实际项目再补齐运维策略。

## 进程崩溃如何处理

崩溃处理分两层：

```text
进程内：UnhandledException 和 ETTask.ExceptionHandler 记录错误
进程外：Watcher 或系统级进程管理负责重新拉起
```

`DotNet/Loader/Init.cs` 中会设置：

```text
AppDomain.CurrentDomain.UnhandledException
ETTask.ExceptionHandler
```

这能帮助记录异常，但不能代替进程守护。

`WatcherComponentSystem` 会启动本机相关进程。生产上还应该配合操作系统或容器层面的自动重启。

## 如何监控集群状态

最基础的监控维度：

```text
进程是否存在
端口是否监听
日志是否持续报错
CPU、内存、网络、磁盘
关键业务指标：在线人数、房间数、匹配等待人数、消息延迟
```

ET 的 StartConfig 能告诉你应该有哪些进程和端口。监控系统应该拿这份配置作为期望状态，再和实际运行状态比对。

## 新人排查清单

1. 连接不上服务端，先看 `StartSceneConfig` 端口和机器 IP。
2. 进程启动但业务无响应，检查目标 Scene 是否在该 Process 里。
3. 本地正常、发布后失败，检查 Config 是否被复制到发布包。
4. 崩溃后没有恢复，检查 Watcher 或系统进程管理。
5. 监控缺失时，先补进程、端口、日志，再补业务指标。
6. 多机部署时，重点检查 `InnerIP`、`OuterIP`、防火墙和数据库地址。
