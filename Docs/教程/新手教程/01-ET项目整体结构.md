# ET项目整体结构

这篇解决一个新手最先遇到的问题：一个 ET8 项目里为什么同时有 Unity 工程、dotnet 工程、共享代码、生成代码、配置表和工具目录。

本仓库是示例项目。你可以把 `Agar` 理解成一个具体游戏模块，把目录结构理解成 ET8 项目的通用组织方式。

## 先看整体分工

ET8 项目通常不是“一个 Unity 工程”这么简单。它更像一组协作工程：

| 目录 | 作用 |
| --- | --- |
| `Unity/` | Unity 客户端工程，负责画面、输入、UI、资源、客户端启动 |
| `DotNet/` | 服务端 dotnet 工程，负责独立启动服务端进程 |
| `Unity/Assets/Scripts/` | 客户端、服务端和共享 C# 源码的主要位置 |
| `Share/` | 代码生成器、分析器、协议和导表工具 |
| `Config/` | 导出的运行配置和业务配置 |
| `Book/` | ET 框架原始参考文档 |
| `Tools/` | 构建、同步、发布等辅助工具 |

新手最容易误解的是：服务端代码虽然放在 `Unity/Assets/Scripts/Hotfix/Server/` 等目录下，但服务端运行时不是 Unity。服务端由 `DotNet/App/Program.cs` 启动，是 dotnet 进程。

## 代码分层

ET 会把代码拆成稳定定义和可热更行为。

| 程序集 | 典型内容 |
| --- | --- |
| `Model` | 不依赖 Unity 表现层的稳定类型，例如实体、组件、协议、配置 |
| `Hotfix` | 不依赖 Unity 表现层的可热更逻辑，例如消息处理、服务端玩法、共享规则 |
| `ModelView` | 客户端表现层稳定类型，例如 UI Component 字段定义 |
| `HotfixView` | 客户端表现层可热更逻辑，例如 UI 创建、按钮响应、资源加载 |

可以用一条简单规则判断：

```text
只是数据结构、组件定义、协议结构 -> Model 或 ModelView
具体行为、消息处理、UI 逻辑、玩法规则 -> Hotfix 或 HotfixView
依赖 UnityEngine、Prefab、Transform、UI -> View 系列
不依赖 Unity 表现能力 -> 非 View 系列
```

本仓库示例：

```text
Unity/Assets/Scripts/Model/Share/Agar/Message/AgarMessage.cs
Unity/Assets/Scripts/Hotfix/Server/Agar/
Unity/Assets/Scripts/ModelView/Client/Agar/UI/
Unity/Assets/Scripts/HotfixView/Client/Agar/UI/
```

## 生成代码放在哪里

ET 项目里很多代码不是手写的，例如协议消息和配置类。

生成结果一般在：

```text
Unity/Assets/Scripts/Model/Generate/Client/
Unity/Assets/Scripts/Model/Generate/Server/
Unity/Assets/Scripts/Model/Generate/ClientServer/
```

`Client` 表示客户端可见，`Server` 表示服务端可见，`ClientServer` 表示双端都可见。

这不是“客户端服务端一起运行在 Unity”的意思。它只是代码生成目标，说明这批类型在客户端和服务端都能引用。

## 配置和启动配置

`Config/` 下有业务配置，也有服务端集群启动配置。

新人要特别注意：

```text
Config/Json/s/StartConfig/Localhost/
Config/Json/s/StartConfig/Release/
Config/Json/s/StartConfig/Benchmark/
```

这些 `StartConfig` 描述机器、进程、区服、Scene 和端口。服务端启动时会根据 `Options.StartConfig` 和 `Options.Process` 选择自己要创建哪些运行对象。

## Book 和 Docs 的区别

`Book/` 是 ET 框架参考资料，适合查背景概念。`Docs/教程/` 是本仓库按新人学习路径整理出来的教程，优先告诉你在这个类型的项目里怎么定位代码、怎么走流程。

遇到问题时建议顺序：

```text
先看 Docs/教程
再用 Book 查概念背景
最后回到源码确认当前项目实际实现
```

## 新人排查清单

1. 先确认你改的是客户端、服务端还是共享逻辑。
2. 依赖 Unity 表现层的代码不要放到服务端逻辑目录。
3. 只改了源码但运行没变化时，检查是否需要 `ET/Compile`。
4. 找协议时先看 `Unity/Assets/Config/Proto/` 和 `Model/Generate/`。
5. 找服务端启动拓扑时先看 `Config/Json/s/StartConfig/`。
6. 不要把 `ClientServer` 理解成运行模式，它是代码生成可见性。
