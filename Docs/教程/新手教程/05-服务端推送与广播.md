# 服务端推送与广播

这篇解释服务端如何主动通知客户端，以及如何给一组玩家广播。

先区分三个词：

```text
响应：客户端请求后，服务端返回给请求者
推送：服务端主动发给某一个客户端
广播：服务端主动发给一组客户端
```

## 推送不是响应

响应依赖 `RpcId`，是某个请求的返回。

推送不依赖客户端当前正在等待的请求。服务端只要找到玩家对应的连接，就可以发送一个 `IMessage`。

本仓库示例：

```text
Match2G_AgarMatchSuccess
Match2G_AgarBattleState
Match2G_AgarBattleResult
```

这些消息不是 `C2G_AgarMatch` 的直接响应，而是 Match Scene 在合适时机主动发给玩家。

## 服务端如何找到玩家连接

玩家登录 Gate 后，Gate 会给 `Player` 和 `PlayerSessionComponent` 注册 Location：

```text
playerSessionComponent.AddLocation(LocationType.GateSession)
player.AddLocation(LocationType.Player)
```

之后其他 Scene 可以通过 `MessageLocationSenderComponent` 按玩家 id 发送消息。

本仓库在房间里封装了：

```csharp
private static void SendToRealPlayer(this AgarRoom self, long playerId, IMessage message)
{
    MessageLocationSenderComponent messageLocationSenderComponent = self.Root().GetComponent<MessageLocationSenderComponent>();
    messageLocationSenderComponent.Get(LocationType.Player).Send(playerId, message);
}
```

这就是“知道玩家 id，就能把消息发给这个玩家当前所在 GateSession”的关键。

## 一对一推送

匹配成功时，Match Scene 给每个真实玩家发送：

```text
Match2G_AgarMatchSuccess
```

位置：

```text
Unity/Assets/Scripts/Hotfix/Server/Agar/Match/AgarMatchComponentSystem.cs
```

逻辑是：

```text
创建房间
把玩家绑定到房间
开始战斗
遍历真实玩家
用 MessageLocationSenderComponent 发 Match2G_AgarMatchSuccess
```

虽然代码里是循环，但每次发送都是对某一个玩家的一对一推送。

## 房间广播

房间状态同步是广播。

位置：

```text
Unity/Assets/Scripts/Hotfix/Server/Agar/AgarRoomSystem.cs
```

核心链路：

```text
TickBattle
 -> BroadcastState
 -> 遍历 RealPlayerIds
 -> 为每个玩家创建 Match2G_AgarBattleState
 -> SendToRealPlayer
```

注意这里不是把同一个对象直接发给所有人，而是给每个玩家创建状态消息。因为 `MyPlayerId`、`MyScore` 这类字段可能因玩家而不同。

## 结束结算广播

战斗结束时：

```text
FinishBattle
 -> 计算排行榜
 -> 持久化战绩
 -> 遍历 RealPlayerIds
 -> 发送 Match2G_AgarBattleResult
 -> 移除房间
```

这也是广播，但每个玩家看到的 `IsWinner`、`MyScore` 不一样。

## 客户端如何接推送

客户端用消息处理器接收推送。

例如战斗状态：

```text
Unity/Assets/Scripts/HotfixView/Client/Agar/NetClient/Match2G_AgarBattleStateHandler.cs
```

处理器拿到 `UIAgarBattle`，然后调用：

```text
RefreshBattleState(message)
```

所以推送链路是：

```text
Match Scene
 -> MessageLocationSenderComponent
 -> GateSession
 -> 客户端 Gate Session
 -> 客户端 MessageHandler
 -> UI 或本地状态刷新
```

## 广播时要注意什么

广播不是“把同一个消息对象发 N 次”这么简单。

建议：

```text
每个玩家需要不同字段时，为每个玩家创建独立消息
发送前确认玩家还在线
高频广播控制频率
广播内容只放客户端需要的数据
战斗状态以服务端权威为准
```

本仓库用 `AgarRoom.SyncInterval` 控制状态同步频率，避免每帧都发网络消息。

## 新人排查清单

1. 推送不到客户端，检查玩家是否注册了 Location。
2. 客户端收到消息但没表现，检查客户端 `MessageHandler` 的 `SceneType`。
3. 广播错人，检查房间里的玩家列表。
4. 每个玩家视角不同，不要复用同一个消息对象。
5. 高频广播卡顿，检查同步间隔和消息大小。
6. 战斗结果不一致，确认结算只在服务端权威逻辑里发生。
