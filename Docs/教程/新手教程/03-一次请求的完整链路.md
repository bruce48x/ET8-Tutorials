# 一次请求的完整链路

这篇解释一个请求从客户端出发，到达服务端，再回到客户端的过程。

先记住两类消息：

```text
Request/Response：客户端发请求，等待服务端返回
Message：只发送，不等待返回，常用于通知、输入上报、广播
```

## 客户端从哪里发请求

本仓库中，客户端业务通常通过 `ClientSenderComponent` 发消息。

请求调用：

```csharp
IResponse response = await root.GetComponent<ClientSenderComponent>().Call(request);
```

无返回消息：

```csharp
root.GetComponent<ClientSenderComponent>().Send(message);
```

例如匹配：

```text
MatchingHelper.Match
 -> ClientSenderComponent.Call(C2G_AgarMatch)
```

移动输入：

```text
ClientSenderComponent.Send(C2G_AgarMove)
```

## 为什么中间有 A2NetClient

客户端主逻辑不直接操作 Gate `Session`，而是把请求转给 NetClient Fiber。

请求链路：

```text
主 Fiber
 -> ClientSenderComponent.Call
 -> ProcessInnerSender.Call(NetClient Fiber, A2NetClient_Request)
 -> A2NetClient_RequestHandler
 -> SessionComponent.Session.Call(真实业务请求)
```

`A2NetClient_RequestHandler` 会取出内部消息里的 `MessageObject`，用 Gate Session 发给服务端，再把服务端响应塞回 `A2NetClient_Response`。

这样主 Fiber 和网络 Fiber 解耦。

## 网络层做了什么

当执行：

```text
Session.Call(C2G_AgarMatch)
```

ET 会做几件事：

```text
给请求分配 RpcId
根据 [Message] id 找到协议编号
序列化消息
通过 Session 的网络服务发送
等待同 RpcId 的响应
反序列化响应并恢复 await
```

这些细节通常不用业务代码手写。业务代码只写消息类型和处理器。

## 服务端如何找到处理器

服务端处理器使用特性声明自己处理哪类消息、运行在哪类 Scene：

```csharp
[MessageSessionHandler(SceneType.Gate)]
public class C2G_AgarMatchHandler : MessageSessionHandler<C2G_AgarMatch, G2C_AgarMatch>
```

这表示：

```text
收到 C2G_AgarMatch
当前 Session 所在 SceneType 是 Gate
就分发到这个 Handler
```

如果 SceneType 不匹配，处理器不会被选中。

## 请求可能跨服务端 Scene

客户端请求先到 Gate，但真正业务不一定在 Gate。

匹配例子：

```text
客户端 C2G_AgarMatch
 -> Gate: C2G_AgarMatchHandler
 -> Gate 通过 MessageSender.Call 发 G2Match_AgarMatch
 -> Match Scene: G2Match_AgarMatchHandler
 -> Match 返回 Match2G_AgarMatch
 -> Gate 返回 G2C_AgarMatch 给客户端
```

移动例子更适合用无返回消息：

```text
客户端 C2G_AgarMove
 -> Gate: C2G_AgarMoveHandler
 -> Gate 通过 MessageSender.Send 发 G2Match_AgarMove
 -> Match Scene 更新房间内玩家方向
```

外网消息和内网消息要区分：

```text
C2G_*  客户端到 Gate
G2C_*  Gate 到客户端响应
G2Match_* Gate 到 Match
Match2G_* Match 到 Gate 或经 Gate 推给玩家
```

命名不是强制语法，但它能帮助读者判断消息方向。

## 返回和通知的区别

请求响应只回给发起者，例如：

```text
C2G_AgarPlayerStats -> G2C_AgarPlayerStats
```

服务端通知可以不是某个请求的直接返回，例如：

```text
Match2G_AgarMatchSuccess
Match2G_AgarBattleState
Match2G_AgarBattleResult
```

客户端接收通知时，会通过 `[MessageHandler(SceneType.Agar)]` 之类的处理器更新 UI 或状态。

## 新人排查清单

1. 请求超时先看服务端有没有对应 Handler。
2. Handler 存在但不触发，检查 `SceneType` 是否匹配。
3. 有响应类型的请求要写 `ResponseType`。
4. 客户端等待响应时，服务端必须返回 Response。
5. 不需要返回的高频输入不要写成 Request。
6. 跨服务端 Scene 时，检查 `StartSceneConfigCategory.Instance.Xxx` 是否能找到目标 Scene。
