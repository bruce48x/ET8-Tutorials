# 客户端开发入门

这篇解释新人最常做的客户端工作：创建新窗口、绑定 prefab、切换界面或场景、理解代码生成和 `ET/Compile`。

本仓库用 `Agar` 模块举例。换到自己的项目时，把 `Agar` 换成你的模块名即可。

## UI 代码放在哪里

ET 客户端 UI 通常分成“稳定定义”和“可热更行为”。

| 内容 | 推荐位置 |
| --- | --- |
| UI 类型常量 | `ModelView/Client/<Module>/UI/UIType.cs` |
| UI Component 字段定义 | `ModelView/Client/<Module>/UI/<UIName>/<UIName>Component.cs` |
| UI 创建、资源加载 | `HotfixView/Client/<Module>/UI/<UIName>/<UIName>Event.cs` |
| 按钮绑定和界面行为 | `HotfixView/Client/<Module>/UI/<UIName>/<UIName>ComponentSystem.cs` |
| UI Prefab | `Unity/Assets/Bundles/UI/<Module>/<UIName>.prefab` |

本仓库示例：

```text
Unity/Assets/Scripts/ModelView/Client/Agar/UI/UIType.cs
Unity/Assets/Scripts/ModelView/Client/Agar/UI/UIAgarLogin/UIAgarLoginComponent.cs
Unity/Assets/Scripts/HotfixView/Client/Agar/UI/UIAgarLogin/UIAgarLoginEvent.cs
Unity/Assets/Scripts/HotfixView/Client/Agar/UI/UIAgarLogin/UIAgarLoginComponentSystem.cs
Unity/Assets/Bundles/UI/Agar/UIAgarLogin.prefab
```

## 如何创建新窗口

创建一个新窗口通常按这个顺序：

1. 在 `UIType` 里加常量。
2. 创建 UI prefab，并放到 Bundles UI 目录。
3. 在 prefab 根节点配置 `ReferenceCollector`。
4. 创建 UI Component 保存控件引用。
5. 创建 UIEvent 加载 prefab。
6. 创建 ComponentSystem 绑定按钮和行为。
7. 在合适的事件或流程里调用 `UIHelper.Create`。

创建链路可以理解为：

```text
UIType 常量
 -> [UIEvent(UIType.Xxx)]
 -> OnCreate 加载 prefab
 -> Object.Instantiate
 -> AddChild<UI>
 -> AddComponent<具体 UI Component>
 -> ComponentSystem.Awake 绑定引用和事件
```

## Prefab 和 ET Component 怎么关联

ET 的 UI Component 不是 `MonoBehaviour`，不会挂在 prefab Inspector 上。

关联发生在 `AUIEvent.OnCreate()`：

```text
加载 prefab
实例化 GameObject
把 GameObject 包成 ET 的 UI Entity
给 UI Entity 添加 UIAgarLoginComponent
```

Prefab 内部子节点通过 `ReferenceCollector` 暴露给代码。

代码里类似：

```csharp
ReferenceCollector rc = self.GetParent<UI>().GameObject.GetComponent<ReferenceCollector>();
self.loginBtn = rc.Get<GameObject>("LoginBtn");
self.account = rc.Get<GameObject>("Account");
self.password = rc.Get<GameObject>("Password");
```

所以 key 必须和 prefab 上配置的引用名一致。

## 界面切换

ET UI 切换通常不是直接加载 Unity 场景，而是通过事件和 UIComponent 管理。

例如登录完成：

```text
LoginHelper.Login
 -> Publish LoginFinish
 -> LoginFinish_RemoveUIAgarLogin
 -> LoginFinish_CreateUIAgarLobby
```

这种方式的重点是：业务状态变化发布事件，UI 订阅事件创建或移除界面。

## 场景切换怎么理解

新手常把两种“场景”混在一起：

| 名称 | 含义 |
| --- | --- |
| Unity Scene | Unity 的场景资源，例如登录场景、战斗场景 |
| ET Scene | ET 运行时的逻辑容器，例如 `SceneType.Agar`、`SceneType.Gate` |

客户端从主城到地下城，可能包含两层变化：

```text
Unity 表现层：加载新的 Unity Scene 或资源
ET 逻辑层：切换 UI、创建玩法 Entity、请求服务端进入房间
```

不要只理解成 `SceneManager.LoadScene`。联网游戏里，场景切换通常还要服务端确认玩家能否进入目标玩法。

本仓库目前的 Agar 战斗入口更偏 UI 和状态切换：

```text
匹配成功
 -> 收到 Match2G_AgarMatchSuccess
 -> 创建 UIAgarBattle
 -> 后续收到战斗状态刷新界面
```

## 代码是如何生成的

客户端会用到两类生成内容：

```text
协议和配置生成代码
Unity 工程里的程序集 dll.bytes
```

协议生成结果看：

```text
Unity/Assets/Scripts/Model/Generate/
```

热更程序集输出看：

```text
Unity/Assets/Bundles/Code/
```

`ET/Compile` 会编译这些程序集并复制成 `.dll.bytes`。如果启用了 dll 加载模式，运行时真正加载的是这些 `.bytes`，不是你刚刚在 IDE 里看到的源码。

## 为什么 ET/Compile 很关键

修改以下内容后，运行前要执行：

```text
Unity 菜单 ET/Compile
快捷键 F6
```

常见需要编译的内容：

```text
新增 UIEvent
新增 ComponentSystem
新增消息 Handler
修改 Hotfix/HotfixView 行为
修改 Model/ModelView 稳定定义
```

如果没执行，现象可能是：

```text
源码明明改了
运行时还是旧行为
新 Handler 不触发
新 UI 不出现
```

## 新人排查清单

1. UI 不显示，先检查 `UIType`、`UIEvent`、prefab 路径。
2. 空引用，检查 `ReferenceCollector` key 是否一致。
3. 登录后没跳界面，检查对应事件是否发布和订阅。
4. 战斗界面不刷新，检查客户端推送 Handler 是否触发。
5. 修改代码没生效，先执行 `ET/Compile`。
6. 场景切换前先想清楚：这是 Unity Scene 切换，还是 ET 逻辑状态切换。
