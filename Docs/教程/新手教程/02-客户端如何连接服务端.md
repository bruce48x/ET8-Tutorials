# 客户端如何连接服务端

这篇解释客户端与服务端的连接是如何建立的。

先记住结论：客户端最终使用的是连接到 Gate 的 `Session`。在拿到 Gate `Session` 之前，它会先通过 Router 找路，再向 Realm 登录，再拿着 Realm 返回的 key 登录 Gate。

## 通用概念

一个典型 ET 登录链路可以拆成四段：

```text
客户端主 Fiber
 -> 创建 NetClient Fiber
 -> 连接 Realm 并请求登录
 -> Realm 分配 Gate 和登录 Key
 -> 客户端连接 Gate 并用 Key 验证
 -> 保存 Gate Session
```

为什么不是直接连 Gate？

因为 Realm 负责入口和分配，Gate 负责玩家长期连接。这样服务端可以有多个 Gate，Realm 根据账号或负载选择一个 Gate。

## Router、Realm、Gate 分别做什么

| 名称 | 作用 |
| --- | --- |
| Router | 帮客户端找到真实服务地址，处理路由连接 |
| Realm | 登录入口，校验账号流程，分配 Gate |
| Gate | 玩家登录后的长期连接入口，处理客户端业务请求 |
| Session | 一条网络连接在 ET 中的对象表示 |

本仓库的客户端连接代码主要在：

```text
Unity/Assets/Scripts/Hotfix/Client/Agar/NetClient/
Unity/Assets/Scripts/Hotfix/Client/Agar/NetClient/Router/
```

## 从 LoginHelper 开始

客户端 UI 或业务入口调用：

```csharp
await LoginHelper.Login(root, account, password);
```

`LoginHelper` 做三件事：

```text
移除旧 ClientSenderComponent
添加新的 ClientSenderComponent
调用 LoginAsync
登录完成后发布 LoginFinish 事件
```

`ClientSenderComponent` 是客户端主逻辑和网络 Fiber 之间的桥。主逻辑不直接持有网络细节，而是通过它 `Call` 或 `Send`。

## 创建 NetClient Fiber

`ClientSenderComponentSystem.LoginAsync()` 会创建一个 `SceneType.NetClient` 的 Fiber：

```text
FiberManager.Instance.Create(... SceneType.NetClient ...)
```

然后主 Fiber 给 NetClient Fiber 发一个内部消息：

```text
Main2NetClient_Login
```

这样做的好处是：网络连接和主逻辑分在不同 Fiber 中，主逻辑只关心“登录完成后得到 PlayerId”。

## NetClient 连接 Realm

`Main2NetClient_LoginHandler` 里先初始化 Router 地址：

```text
RouterAddressComponent
NetComponent
```

然后通过账号选择 Realm 地址：

```text
routerAddressComponent.GetRealmAddress(account)
```

客户端不会直接裸连 Realm，而是调用：

```text
netComponent.CreateRouterSession(realmAddress, account, password)
```

`CreateRouterSession` 会向 Router 申请连接，并创建一个 `Session`。

## Realm 返回 Gate 信息

客户端通过 Realm `Session` 发送：

```text
C2R_Login
```

服务端处理器在：

```text
Unity/Assets/Scripts/Hotfix/Server/Agar/Realm/C2R_LoginHandler.cs
```

Realm 做的核心事情：

```text
根据账号选择 Gate
向 Gate 请求登录 Key
把 Gate 地址、Key、GateId 返回给客户端
关闭临时 Realm Session
```

返回消息是：

```text
R2C_Login
```

里面包含：

```text
Address
Key
GateId
```

## 客户端连接 Gate

客户端拿到 Realm 返回结果后，再创建 Gate `Session`：

```text
CreateRouterSession(NetworkHelper.ToIPEndPoint(r2CLogin.Address), account, password)
```

然后把这个 Session 保存到：

```text
SessionComponent.Session
```

之后业务请求都通过这个 Gate Session 发出。

客户端再发送：

```text
C2G_LoginGate
```

服务端 Gate 处理器在：

```text
Unity/Assets/Scripts/Hotfix/Server/Agar/Gate/C2G_LoginGateHandler.cs
```

Gate 用 `Key` 查账号，验证成功后创建或复用 `Player`，并把 `SessionPlayerComponent` 绑定到当前 `Session`。

## 最终连接结果

登录完成后，客户端拥有：

```text
PlayerComponent.MyId
ClientSenderComponent
NetClient Fiber
SessionComponent.Session -> Gate Session
```

后续匹配、移动、查询战绩等请求都不再走 Realm，而是走 Gate。

## 新人排查清单

1. 连接失败先区分是 Router、Realm 还是 Gate 阶段失败。
2. Realm 登录成功但 Gate 登录失败，优先检查 `Key` 和 `GateId`。
3. 业务请求发不出去，检查 `SessionComponent.Session` 是否存在。
4. 多次登录状态混乱，检查旧 `ClientSenderComponent` 是否移除。
5. Gate 收到请求但找不到玩家，检查 `SessionPlayerComponent` 是否绑定。
