# 服务端如何热更

这篇解释服务端热更的日常流程。

结论先说：服务端是 dotnet 进程，热更核心是重新加载 `Hotfix.dll`，重建 `CodeTypes`，让后续消息处理和系统发现使用新代码。

## 服务端加载哪些程序集

服务端入口在：

```text
DotNet/App/Program.cs
DotNet/Loader/Init.cs
DotNet/Loader/CodeLoader.cs
```

`DotNet/Loader/CodeLoader.cs` 会：

```text
在当前 AppDomain 里找到 Model 程序集
通过 AssemblyLoadContext 加载 Hotfix.dll
创建 CodeTypes
反射调用 ET.Entry.Start
```

服务端热更目标主要是：

```text
Hotfix.dll
Hotfix.pdb
```

## Hotfix.dll 从哪里来

服务端 Hotfix 工程：

```text
DotNet/Hotfix/DotNet.Hotfix.csproj
```

它会编译：

```text
Unity/Assets/Scripts/Hotfix/Client/**/*.cs
Unity/Assets/Scripts/Hotfix/Server/**/*.cs
Unity/Assets/Scripts/Hotfix/Share/**/*.cs
```

实际服务端运行时使用 `Hotfix.dll`。发布时要确认新 dll 已经进入服务端运行目录。

## Reload 做什么

服务端 `CodeLoader.Reload()` 做几件事：

```text
卸载旧 AssemblyLoadContext
GC.Collect
创建新的 AssemblyLoadContext
读取 ./Hotfix.dll 和 ./Hotfix.pdb
加载新 Hotfix 程序集
重新创建 CodeTypes
执行 codeTypes.CreateCode()
```

这会让新的 Handler、System、事件处理器等被重新发现。

## 如何触发 Reload

本仓库有控制台处理器：

```text
Unity/Assets/Scripts/Hotfix/Share/Module/Console/ReloadDllConsoleHandler.cs
```

它处理：

```text
ConsoleMode.ReloadDll
```

并调用：

```text
CodeLoader.Instance.Reload()
```

控制台组件在：

```text
Unity/Assets/Scripts/Hotfix/Share/Module/Console/ConsoleComponentSystem.cs
```

它读取命令行输入，并分发给对应 `IConsoleHandler`。

## M2A_Reload 和 A2M_Reload

协议里还有：

```text
M2A_Reload
A2M_Reload
```

它们是服务端内部 reload 管理消息的基础类型，定义在：

```text
Unity/Assets/Config/Proto/InnerMessage_S_20001.proto
Unity/Assets/Scripts/Model/Generate/Server/Message/InnerMessage_S_20001.cs
```

实际项目可以用管理进程或运维工具向目标进程发送 reload 消息，而不是手动登录控制台输入。

## 热更不等于状态重置

这是服务端热更最容易踩坑的地方。

Reload 会更新代码发现表，但不会自动重建所有已经存在的 Entity 和 Component。

例如：

```text
已有房间还在
已有 Player 还在
已有 Component 字段值还在
旧对象的状态不会因为新 dll 自动迁移
```

所以热更适合：

```text
修改 Handler 逻辑
修改后续 Tick 逻辑
修复新请求处理
调整不需要状态迁移的行为
```

不适合直接无脑修改：

```text
已有 Component 字段结构
关键 Entity 生命周期
状态机中间状态含义
数据库结构
协议字段兼容性
```

## 新人排查清单

1. Reload 后逻辑没变，确认运行目录里的 `Hotfix.dll` 已更新。
2. 新 Handler 不触发，检查 `CodeTypes` 是否重新创建。
3. 热更后报类型或字段问题，检查已有对象状态和新代码是否兼容。
4. 修改 Model 稳定定义时，不要只替换 Hotfix。
5. 多进程集群要确认每个目标进程都 reload。
6. 生产热更前先在同样启动配置下演练。
