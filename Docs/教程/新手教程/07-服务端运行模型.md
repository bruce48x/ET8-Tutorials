# 服务端运行模型

这篇回答两个常见问题：服务端是怎么跑起来的？`ClientServer` 模式是不是表示服务端运行在 Unity？

结论先说：服务端运行时是 dotnet 进程，不是 Unity。`ClientServer` 是代码可见性和编译模式，不是服务端运行方式。

## 服务端入口

服务端入口在：

```text
DotNet/App/Program.cs
```

主循环非常直接：

```text
Entry.Init()
Init.Start()
while true:
    init.Update()
    init.LateUpdate()
```

这说明服务端有自己的进程和循环，不依赖 Unity Editor 的播放按钮。

## Loader 做什么

服务端启动后进入：

```text
DotNet/Loader/Init.cs
```

这里会：

```text
解析命令行 Options
初始化 Logger
设置 ETTask.ExceptionHandler
添加 TimeInfo
添加 FiberManager
添加 CodeLoader
```

`CodeLoader` 再加载 Model 和 Hotfix 程序集，找到 `ET.Entry.Start` 并执行。

## Options 是什么

命令行参数解析到：

```text
Unity/Assets/Scripts/Core/World/Module/Options/Options.cs
```

重要字段：

| 字段 | 作用 |
| --- | --- |
| `AppType` | 进程类型，例如 `Server`、`Watcher` |
| `StartConfig` | 使用哪套启动配置，例如 `StartConfig/Localhost` |
| `Process` | 当前进程 id |
| `Develop` | 运行模式 |
| `LogLevel` | 日志等级 |

服务端启动时通常会指定：

```text
--AppType Server --StartConfig StartConfig/Localhost --Process 1
```

## Process、Scene、Fiber

ET 服务端不是“一个进程里写一堆全局单例”。

它通常按这几层组织：

```text
物理机 Machine
 -> 进程 Process
 -> 逻辑场景 Scene
 -> Fiber
 -> Entity/Component/System
```

`StartProcessConfig` 决定有哪些进程。`StartSceneConfig` 决定每个进程里有哪些服务端 Scene。

本仓库 Localhost 示例：

```text
Process 1
 -> Realm
 -> Gate1
 -> Gate2
 -> Location
 -> Match
 -> RouterManager
 -> Router01-04
```

这些 Scene 可以在同一个进程里，也可以在不同进程里，取决于启动配置。

## SceneType 决定 Handler 归属

服务端消息处理器会标注运行在哪种 Scene：

```text
[MessageSessionHandler(SceneType.Gate)]
[MessageHandler(SceneType.Match)]
```

这不是文件夹名决定的，而是运行时 SceneType 决定的。

例如：

```text
C2G_AgarMatchHandler -> Gate
G2Match_AgarMatchHandler -> Match
```

## ClientServer 是什么

`ClientServer` 常出现在生成代码目录：

```text
Unity/Assets/Scripts/Model/Generate/ClientServer/
```

它表示这批代码客户端和服务端都能引用。

它不表示：

```text
客户端和服务端运行在同一个 Unity 进程
```

它表示：

```text
这批类型是双端共享的编译目标
```

例如协议 DTO、配置类和双端共享结构可能会放在 `ClientServer` 生成目录。

## Unity 中的服务端代码为什么能被 dotnet 用

本仓库服务端项目会引用 Unity 目录下的服务端源码。

例如：

```text
DotNet/Hotfix/DotNet.Hotfix.csproj
```

会编译：

```text
Unity/Assets/Scripts/Hotfix/Server/**/*.cs
Unity/Assets/Scripts/Hotfix/Share/**/*.cs
```

也就是说，源码放在 Unity 工程目录里，是为了双端共享和开发方便；服务端运行时仍然是 dotnet 编译和加载这些代码。

本仓库目前只有一个 Agar 游戏模块。`Agar` 的 `SceneType` 注册在：

```text
Unity/Assets/Scripts/Hotfix/Server/Agar/EntryEvent2_InitServer.cs
```

## 跟一遍服务端启动

现在你打开 IDE，实际跟踪一次服务端从启动到可以接受请求的过程。

**1. 入口：Program.Main**

打开 `DotNet/App/Program.cs`，从 `Main()` 开始：

```csharp
Entry.Init();        // 确保 Model 程序集被加载
Init init = new();
init.Start();        // 创建 CodeLoader → 加载 Hotfix.dll → 创建 CodeTypes
```

**2. 创建 FiberManager 和 CodeLoader**

`Init.Start()` 在 `DotNet/Loader/Init.cs`。它依次创建了 `TimeInfo`、`FiberManager`、`CodeLoader`。`CodeLoader` 的 `Awake` 方法会加载 `Hotfix.dll`，然后反射调用 `ET.Entry.Start`。

**3. ET.Entry.Start 创建所有 Scene 的 Fiber**

`ET.Entry.Start` 在 Model 程序集中。它会读取 `StartSceneConfig`，为每个配置的 Scene 创建一个对应的 Fiber。Fiber 是 ET 中轻量级的逻辑隔离单位——每个 Scene 在自己的 Fiber 中运行，有自己的 Entity 树和 System 调度。

**4. 每个 Scene 的 Fiber 开始运行**

以 Gate Scene 为例。当 Gate Fiber 被创建后，框架会执行该 SceneType 上注册的 `[EntitySystem]` Awake 方法。这包括：
- 添加 `NetComponent`（监听端口，接受连接）
- 添加 `MessageDispatcher`（消息分发）
- 初始化 `Location` 注册
- 执行模块特定的初始化逻辑

**5. 验证：观察 Console 日志**

启动服务端后，你应该在 Console 中看到类似以下日志：

```text
[NLogger] 日志系统初始化完成
CodeLoader: 加载 Hotfix.dll 成功
CodeTypes: 已扫描 X 个类型
Entry.Start: 开始创建 Scene Fiber
Realm 启动在 0.0.0.0:30002
Gate1 启动在 0.0.0.0:30003
Gate2 启动在 0.0.0.0:30004
...
```

此时服务端已准备好接受客户端连接。

**启动时序图：**

```text
Program.Main()
  └─ Init.Start()
       ├─ Logger 初始化
       ├─ FiberManager 初始化
       └─ CodeLoader.Awake()
            ├─ 找到 Model 程序集
            ├─ LoadHotfix() → AssemblyLoadContext 加载 Hotfix.dll
            ├─ 创建 CodeTypes → 扫描所有 [EntitySystem]、[MessageHandler] 等
            └─ 反射调用 ET.Entry.Start
                 └─ 读取 StartSceneConfig
                      └─ 为每个 Scene 创建 Fiber
                           └─ 每个 Fiber 初始化自己的 Entity/Component 树
```

## 新人排查清单

1. 服务端问题先看 dotnet 进程日志，不要只看 Unity Console。
2. Handler 不触发，检查目标 Scene 是否存在并运行。
3. `ClientServer` 是代码生成目标，不是运行模式。
4. 服务端启动失败，检查命令行 `AppType`、`StartConfig`、`Process`。
5. 找不到服务端代码时，同时看 `DotNet/*.csproj` 和 `Unity/Assets/Scripts/Hotfix/Server/`。
6. 多 Scene 通信失败，检查 `StartSceneConfig` 和目标 `ActorId`。
