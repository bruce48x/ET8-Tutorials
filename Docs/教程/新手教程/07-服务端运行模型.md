# 服务端运行模型

这篇回答两个常见问题：服务端是怎么跑起来的？`ClientServer` 模式是不是表示服务端运行在 Unity？

结论先说：服务端运行时是 dotnet 进程，不是 Unity。`ClientServer` 是代码可见性和编译模式，不是服务端运行方式。

## 服务端入口

服务端入口在：

```text
DotNet/App/Program.cs
```

主循环非常直接：

```text
Entry.Init()
Init.Start()
while true:
    init.Update()
    init.LateUpdate()
```

这说明服务端有自己的进程和循环，不依赖 Unity Editor 的播放按钮。

## Loader 做什么

服务端启动后进入：

```text
DotNet/Loader/Init.cs
```

这里会：

```text
解析命令行 Options
初始化 Logger
设置 ETTask.ExceptionHandler
添加 TimeInfo
添加 FiberManager
添加 CodeLoader
```

`CodeLoader` 再加载 Model 和 Hotfix 程序集，找到 `ET.Entry.Start` 并执行。

## Options 是什么

命令行参数解析到：

```text
Unity/Assets/Scripts/Core/World/Module/Options/Options.cs
```

重要字段：

| 字段 | 作用 |
| --- | --- |
| `AppType` | 进程类型，例如 `Server`、`Watcher` |
| `StartConfig` | 使用哪套启动配置，例如 `StartConfig/Localhost` |
| `Process` | 当前进程 id |
| `Develop` | 运行模式 |
| `LogLevel` | 日志等级 |

服务端启动时通常会指定：

```text
--AppType Server --StartConfig StartConfig/Localhost --Process 1
```

## Process、Scene、Fiber

ET 服务端不是“一个进程里写一堆全局单例”。

它通常按这几层组织：

```text
物理机 Machine
 -> 进程 Process
 -> 逻辑场景 Scene
 -> Fiber
 -> Entity/Component/System
```

`StartProcessConfig` 决定有哪些进程。`StartSceneConfig` 决定每个进程里有哪些服务端 Scene。

本仓库 Localhost 示例：

```text
Process 1
 -> Realm
 -> Gate1
 -> Gate2
 -> Location
 -> Match
 -> RouterManager
 -> Router01-04
```

这些 Scene 可以在同一个进程里，也可以在不同进程里，取决于启动配置。

## SceneType 决定 Handler 归属

服务端消息处理器会标注运行在哪种 Scene：

```text
[MessageSessionHandler(SceneType.Gate)]
[MessageHandler(SceneType.Match)]
```

这不是文件夹名决定的，而是运行时 SceneType 决定的。

例如：

```text
C2G_AgarMatchHandler -> Gate
G2Match_AgarMatchHandler -> Match
```

## ClientServer 是什么

`ClientServer` 常出现在生成代码目录：

```text
Unity/Assets/Scripts/Model/Generate/ClientServer/
```

它表示这批代码客户端和服务端都能引用。

它不表示：

```text
客户端和服务端运行在同一个 Unity 进程
```

它表示：

```text
这批类型是双端共享的编译目标
```

例如协议 DTO、配置类和双端共享结构可能会放在 `ClientServer` 生成目录。

## Unity 中的服务端代码为什么能被 dotnet 用

本仓库服务端项目会引用 Unity 目录下的服务端源码。

例如：

```text
DotNet/Hotfix/DotNet.Hotfix.csproj
```

会编译：

```text
Unity/Assets/Scripts/Hotfix/Server/**/*.cs
Unity/Assets/Scripts/Hotfix/Share/**/*.cs
```

也就是说，源码放在 Unity 工程目录里，是为了双端共享和开发方便；服务端运行时仍然是 dotnet 编译和加载这些代码。

## 新人排查清单

1. 服务端问题先看 dotnet 进程日志，不要只看 Unity Console。
2. Handler 不触发，检查目标 Scene 是否存在并运行。
3. `ClientServer` 是代码生成目标，不是运行模式。
4. 服务端启动失败，检查命令行 `AppType`、`StartConfig`、`Process`。
5. 找不到服务端代码时，同时看 `DotNet/*.csproj` 和 `Unity/Assets/Scripts/Hotfix/Server/`。
6. 多 Scene 通信失败，检查 `StartSceneConfig` 和目标 `ActorId`。
