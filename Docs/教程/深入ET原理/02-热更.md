# 热更

这篇解释 ET 热更的底层思路：为什么要拆程序集，客户端和服务端热更为什么不同，重载代码有哪些边界。

如果你只想知道怎么操作，先看：

- [../新手教程/09-客户端如何热更.md](../新手教程/09-客户端如何热更.md)
- [../新手教程/10-服务端如何热更.md](../新手教程/10-服务端如何热更.md)

## 热更的核心问题

热更本质上是在程序运行后替换一部分逻辑。

要做到这一点，必须先回答：

```text
哪些代码可以被替换？
哪些代码必须稳定存在？
新代码如何被发现？
已有对象怎么办？
客户端和服务端运行环境有什么差异？
```

ET 的答案是：拆程序集，并用 `CodeLoader` 和 `CodeTypes` 重新发现框架类型。

## 为什么拆 Model 和 Hotfix

ET 把代码拆成：

```text
Model
Hotfix
ModelView
HotfixView
```

这不是为了目录好看，而是为了定义边界。

`Model` 和 `ModelView` 更偏稳定定义：

```text
Entity 类型
Component 类型
协议 DTO
配置类型
UI Component 字段结构
```

`Hotfix` 和 `HotfixView` 更偏可替换行为：

```text
System 方法
消息 Handler
事件处理
UI 创建和按钮逻辑
玩法规则
```

稳定定义越少变化，热更风险越低。行为逻辑越集中在 Hotfix，越容易替换。

## CodeTypes 做什么

ET 里很多能力依赖扫描类型：

```text
[EntitySystemOf]
[MessageHandler]
[MessageSessionHandler]
[Event]
[ConsoleHandler]
```

`CodeTypes` 会拿到一组程序集，扫描其中的类型和特性，建立框架运行需要的映射。

重载后重新创建 `CodeTypes`，新的 Handler、System、Event 才能被框架发现。

所以热更不是“把 dll 文件覆盖掉就完了”，还要让 ET 重新扫描和注册。

## 客户端热更为什么需要 HybridCLR

客户端打包后，尤其是 IL2CPP 平台，C# 代码不再是普通桌面 .NET 那种动态加载环境。

HybridCLR 提供运行时加载热更新程序集的能力，并处理 AOT 元数据补充问题。

客户端 `CodeLoader` 会在不同环境下选择：

```text
非 Editor：从资源系统加载 dll.bytes
Editor + EnableDll：从 CodeDir 加载 dll.bytes
Editor + 非 EnableDll：直接找当前 AppDomain 程序集
```

IL2CPP 下还可能需要：

```text
RuntimeApi.LoadMetadataForAOTAssembly
```

这就是 `Assets/Bundles/AotDlls/` 存在的原因。

## 服务端热更为什么用 AssemblyLoadContext

服务端是 dotnet 进程，环境和客户端不同。

服务端 `DotNet/Loader/CodeLoader.cs` 使用：

```text
AssemblyLoadContext("Hotfix", true)
LoadFromStream(Hotfix.dll, Hotfix.pdb)
```

Reload 时：

```text
卸载旧 AssemblyLoadContext
GC.Collect
重新加载 Hotfix.dll
重新创建 CodeTypes
```

这利用的是 .NET 自己的动态加载机制，不需要 HybridCLR。

## 为什么已有对象不会自动变新

这是理解热更边界最重要的一点。

运行时已经存在的 Entity 和 Component，有自己的字段和值：

```text
玩家对象已经创建
房间对象已经创建
UI 对象已经创建
组件字段已经有值
```

Reload 新代码后，框架可以让后续分发使用新的 Handler 或 System，但不会自动把所有旧状态迁移成新结构。

例如你把一个 Component 字段改名、删掉或改变含义，已有对象不会神奇地知道怎么迁移。

所以热更更适合：

```text
修复处理逻辑
调整计算规则
新增不破坏旧状态的 Handler
修复 UI 行为
```

更危险的是：

```text
修改 Entity/Component 结构
改变协议兼容性
改变持久化数据结构
改变对象生命周期
改变启动流程
```

## 客户端和服务端热更的共同点

共同点：

```text
都有稳定程序集和热更程序集
都需要重新发现 CodeTypes
都要注意已有对象状态
都不适合随意修改底层启动链路
```

## 客户端和服务端热更的差异

差异：

| 维度 | 客户端 | 服务端 |
| --- | --- | --- |
| 运行环境 | Unity、Mono 或 IL2CPP | dotnet 进程 |
| 动态加载 | HybridCLR + dll.bytes | AssemblyLoadContext + Hotfix.dll |
| 资源来源 | Bundles/Code、AotDlls | 运行目录 dll |
| 主要风险 | AOT 元数据、资源版本、平台兼容 | 多进程一致性、在线状态、对象迁移 |
| 重载入口 | `ET/Reload`、`CodeLoader.Reload()` | 控制台、管理消息、`CodeLoader.Reload()` |

## 好的热更设计习惯

1. 把容易变化的行为放到 Hotfix。
2. 稳定类型字段谨慎改。
3. 协议新增字段要考虑兼容。
4. 热更前确认所有目标进程和客户端资源版本。
5. 高频在线状态不要依赖重载自动迁移。
6. 把“操作流程”和“原理边界”分开理解。

## 新人排查清单

1. 热更后新代码没生效，检查是否重新创建 `CodeTypes`。
2. 客户端 IL2CPP 异常，检查 HybridCLR 和 AOT 元数据。
3. 服务端 reload 后仍旧逻辑，检查运行目录的 `Hotfix.dll`。
4. 新字段为空或状态错乱，检查已有对象是否需要迁移。
5. 多进程环境只 reload 一个进程，可能导致协议或逻辑不一致。
6. 不确定能否热更时，先判断改动属于稳定定义还是行为逻辑。
